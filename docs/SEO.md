# Search foundation and 90-day plan

Implemented: static semantic HTML, page titles/descriptions, canonical URLs, Open Graph/PNG social preview, Twitter summary card, sitemap, controlled robots, Person/WebSite JSON-LD, CreativeWork JSON-LD on published projects, breadcrumbs, responsive HTML images, internal navigation, language metadata, and noindex protection before launch. JSON-LD syntax is checked locally; Google rich-result eligibility is not claimed. Published project pages also include BreadcrumbList structured data. No ratings, awards, fabricated client results or keyword volumes are used.

## Intent map (qualitative hypotheses, not measured volumes)

Home: independent graphic designer in Bangladesh with international availability.
Work: graphic design portfolio, supported by actual disciplines once work is added.
Services: brand identity, campaign, packaging and motion design services.
About: Nafis designer identity and working approach.
Case studies: actual project subject + actual discipline, each with unique factual context.
Lab: interactive SVG typography poster experiment.
Contact: direct professional project inquiries.

Avoid near-duplicate service landing pages. Publish individual service pages only when original, useful material justifies them. Images need descriptive filenames and specific alt text, with nearby factual captions. After publishing artwork, consider an image sitemap if image discovery remains limited; images are already normal crawlable HTML elements.

## Search Console

For the free pages.dev hostname, add a URL-prefix property using the exact HTTPS URL. Download the verification HTML file from Google into public/ and redeploy; verify only after the file is publicly available. A domain property instead requires control of DNS and its TXT verification record. Do not invent a verification token. Submit `https://<actual-host>/sitemap-index.xml`. Inspect home and representative projects, confirm indexing is allowed and the canonical is correct, and request indexing sparingly. No property has been created or submitted during this work.

## Days 1–30: establish real evidence

Publish 4–6 approved projects with genuine role descriptions and useful captions. Check every page, Search Console verification, sitemap and URL Inspection. Keep a baseline of impressions, clicks, query relevance, indexed pages and image-search performance. Run Lighthouse on production; treat its numbers as lab diagnostics, not field metrics. Review social previews. Link the site from verified professional profiles only; no invented backlink claims.

## Days 31–60: add useful context

Use actual client questions and project decisions to choose one or two original articles. Explain a real typography, packaging or campaign decision with firsthand examples. Add internal links between related projects and services. Share one factual project breakdown on an existing verified professional platform, linking to its permanent case study. Review search queries weekly for relevance, not just counts.

## Days 61–90: improve what people use

Review impressions and click-through rates per page, engagement through actual inquiries, image search, and Core Web Vitals when enough real-user data exists. Improve weak titles or unclear copy based on evidence. Add another strong project when approved. Refresh images that load too slowly. Fix coverage issues before creating more pages. Compare the same periods and note that small datasets are inconclusive. No rankings, traffic or rich results are guaranteed.
