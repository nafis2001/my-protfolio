# Adding authentic work

1. Obtain Nafis’s approved artwork and publication permission. Keep original masters separately; put web source files in `src/assets/projects/<slug>/`.
2. Copy `docs/project-template.md.example` into `src/content/projects/<slug>.md` and fill in factual information. Default status must remain draft.
3. Use descriptive filenames and alt text describing the actual image. Astro reads image dimensions from local imports; do not guess dimensions or force cropping. WebP variants are generated by Astro Image with responsive srcset. Huge masters should be converted to sensible web sources before import; retain originals outside the website.
4. Add Markdown sections only when supported: brief, challenge, idea, exploration, execution, details, delivered work. Omit unsupported narrative and undocumented results.
5. Run check, build, and validate. Inspect the page using a temporary local published status before restoring draft, or publish only after approval. Drafts have no route, gallery entry, or sitemap entry.
6. Set status published after content and rights review. Categories appear only when represented by published work. Display order controls both reading order and gallery rhythm; there is no CSS reordering or cropping.

Schema fields: file ID, slug, title, category, year, client/personal status, role, description, tags, featured, order, status, media, externalLinks, seo. Media dimensions are inferred and validated through Astro image metadata. For motion, use an approved poster image as src and add video with src (a local public path ending .mp4 or .webm), width, height, and hasSpeech. Videos use native controls, playsinline and preload=none; no autoplay. If hasSpeech is true, a captions path to an English .vtt file is required by schema validation. Include a transcript in project Markdown when useful. External presentations can also be linked through externalLinks.

The complete-image link opens the full optimized source in a new tab, with normal browser zoom. This is the accessible image-viewing fallback instead of an unnecessary modal.

## Articles

No articles are published yet. Copy docs/note-template.md.example into src/content/notes/<slug>.md, write a complete original article, and keep status draft until approved. The existing schema validates slug, title, description, publishedAt, optional updatedAt, status, and tags. Future-dated and draft articles have no public route. Published articles receive Article JSON-LD and crawlable links; Notes joins the main navigation once two articles exist. The empty Notes page stays noindex. Article URLs enter the sitemap; the optional Notes directory is intentionally omitted. Do not fill it with generated search bait.

## Missing-content inventory

Required for portfolio launch: 4–6 approved project collections, accurate titles/categories/years/roles, client vs personal status, permission to publish, meaningful captions and alt text, and at least concise factual project descriptions. Process images and outcomes are optional; include only documented material. A portrait, professional profile URLs, and fuller biography are optional. Email and telephone were supplied and confirmed during implementation. Confirm final public domain after hosting is created.

## Motion example

```yaml
media:
  - src: ../../assets/projects/your-project/poster.webp
    alt: Describe the actual motion sequence.
    video:
      src: /media/your-project/sequence.webm
      width: 1920
      height: 1080
      hasSpeech: true
      captions: /media/your-project/captions.vtt
```

Keep exported motion files in public/media and retain masters separately. Check file size and native playback on Safari and Android before release.
